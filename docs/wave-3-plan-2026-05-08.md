### W3-02 — Step09Acceptance + auto WarrantyCard

**Why critical**: Acceptance pass tạo `WarrantyCard` tự động là điểm xoay trục giữa "thi công" và "bảo hành". Hiện hardcode literal → fail-prone.

**Files**:
- `src/pages/shared/JourneySteps/Step09Acceptance.tsx` — rewrite (~300 dòng).
  - Form acceptance criteria (checklist hạng mục bàn giao).
  - Form ghi nhận `HandoverIssue` (lỗi tại bàn giao) — embed vào HandoverAcceptance hay schema riêng (verify MCP).
  - Status `passed | passed_with_issues | rejected`.
- **Trigger script** trên schema `HandoverAcceptance.save`:
  - Nếu `status='passed'` AND `WarrantyCard` chưa tồn tại cho journey này → auto create.
  - Trigger này CÓ THỂ là backend (qua `schema-set_trigger_script` MCP) HOẶC FE-driven (sau khi save acceptance, gọi `warrantyCardService.create`).
  - **Khuyến nghị**: backend trigger để đảm bảo idempotent + tránh dùng FE workaround. Cần dùng `mcp__bac-mcp__schema-set_trigger_script`.
- `src/components/journey/RecordHandoverIssueModal.tsx` (~100 dòng).

**Verify**: Hoàn thành acceptance với `status='passed'` → check WarrantyCard mới được tạo với `journey_id = X` → Step11Maintain/Step12Warranty bắt đầu render dữ liệu thật.

**Effort**: L (~3-4 ngày, gồm thiết kế trigger script).

## Verification end-to-end (cuối Wave 3)

1. **Build clean**: `npx tsc -b --noEmit; echo $?` → exit 0.
2. **Smoke flow contract**: PM tạo Contract v1 → sửa thành v2 với lý do → trigger e-sign → status `signed`.
3. **Smoke flow acceptance → warranty**: PM hoàn thành Step09Acceptance `status='passed'` → kiểm tra WarrantyCard tự động tạo với `journey_id = X` → mở Step11/Step12 thấy WarrantyCard render.
4. **Smoke flow receipt**: KT mở Step10Payment → "Ghi nhận thu" milestone đợt 1 50% → kiểm tra `PaymentReceipt` tạo, milestone status `partially_paid → paid`.
5. **Smoke flow warranty case**: Khách báo lỗi → KT/GS tạo WarrantyCase từ Step12 → tạo WarrantyVisit lịch hẹn → cron WarrantyReminder fire (nếu đã wire).
6. **KT pages**: `/admin/kt/warranty/cards` + `/admin/kt/warranty/schedule` không còn ComingSoon.
7. **Schema sanity**: Mọi schema được dùng đều `mcp schema-search` confirm tồn tại; trigger scripts (nếu có) được wire qua `schema-set_trigger_script`.
